# Public content data

These JSON files are the planned single source of truth for repeatable public content. Keep customer-approved copy and verified claims here; the site should render these records rather than maintain competing copies in page markup.

The empty `items` arrays are intentional. Add only approved, fact-checked records. Do not treat an empty collection as a published claim or proof point.

| File | Used by |
|---|---|
| `case-studies.json` | Case-study cards and results pages |
| `testimonials.json` | Testimonial quotes and attribution |
| `faqs.json` | Visible FAQ and FAQ structured data |
| `pricing.json` | Packages, price ranges, inclusions, and calculator assumptions |
| `trust-signals.json` | Office, governance, security, and certification details |

Keep personal/customer data out of these public files unless explicit publication consent is recorded. Do not put credentials, API keys, or internal lead records here.
